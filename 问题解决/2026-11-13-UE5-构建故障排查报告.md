# UE 5.6.1 构建故障排查报告

- **日期**：2026-11-12 ～ 2026-11-13
- **机器**：`01YXHY1728`（域 `YXHY`，用户 `xiaoyang.yang`，UAC 已关闭 `EnableLUA=0`）
- **工程**：`D:\Work\dev_git\UnrealEngine561`（Git 管理的 UE 5.6.1 源码）
- **结论先行**：三个看似无关的故障，根因是同一个 —— **仓库目录树被打了 `Low` 完整性标签，导致从它启动的进程全部被降级**。清除该标签后全部恢复。

## 1. 故障现象

| # | 现象 | 报错原文（摘要） |
|---|------|------------------|
| A | `GenerateProjectFiles.bat` / VS 构建在依赖检查阶段失败 | `UnrealEngine.CSharp.targets(45,5): error MSB3491: 未能向文件"C:\Users\...\Temp\DotnetDepends-*\*.dep.csv"写入命令行。Access to the path ... is denied.` |
| B | UBA 执行器无法创建会话目录 | `UbaStorageServer - Failed to create directory C:\ProgramData\Epic\UnrealBuildAccelerator\sessions\<id> (Access is denied.)`，重试 138 万次 |
| C | IncrediBuild 完全不参与构建 | `Using XGE executor to run N action(s)` → `Processing is unable to continue due to the Agent Service is not running.` → 4 秒内失败 |

---

## 2. 根因

`D:\Work\dev_git\UnrealEngine561` 整棵目录树带有强制完整性标签：

```
Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)
```

该标签由 **Codex / agent 沙盒**在历史操作中写入（同源的还有 `CodexSandboxUsers` 组、`S-1-4-…` 授权、`Everyone:(CI)(DENY)(S,DC)` 等 ACL 痕迹）。

**关键机制**：在这台机器上，**从 Low 标签目录启动的程序会被降到 Low/Medium 完整性**。于是整条构建链从 `dotnet` 开始就掉级：

```
pwsh / VS        High
 └ cmd.exe       High      （普通 shell 链正常，不受影响）
 └ dotnet.exe    Medium    ← 从仓库内启动，被降级
    └ MSBuild 任务 / cl.exe / xgConsole   Low
```

由此产生三个故障：

- **Low 进程写不进 Medium/无标签目录** → 现象 A、B
- **IncrediBuild 的 XGE 拒绝 Low 调用方** → 现象 C（报错文案误导为"服务未运行"）

### 3.1 A/B 对照（同一命令、同一 ACL，只改标签）

对 `EpicGames.OIDC.csproj` 执行 `-t:Scan`，`OutputPath` 分别指向两个目录：

| 目录 | 标签 | 结果 |
|------|------|------|
| `%TEMP%\ab_medium` | `Medium (I)(OI)(CI)(NW)` | **MSB3491，0 个文件** |

两个目录的 DACL 完全相同（当前用户均为完全控制），因此排除"权限不足"。

### 3.2 任务进程自报身份

让 MSBuild 的 `Exec` 任务执行 `whoami /all`（`TMP` 指向 Low 目录以便先能写文件）：

```
Mandatory Label\Low Mandatory Level   S-1-16-4096
```

### 3.3 位置决定完整性（决定性实验）

同一份 `dotnet.exe` 二进制，仅改变所在目录：

| 位置 | 进程完整性 |
|------|-----------|
| `…\UnrealEngine561\Engine\Binaries\ThirdParty\DotNet\8.0.300\win-x64\dotnet.exe` | **Medium** |
| 拷贝到 `C:\dotnet_test\8.0.300\win-x64\dotnet.exe`（无标签） | **High** |

对照组：从同一个 High shell 启动 `notepad.exe` → High（说明不是 shell 的问题）。

### 3.4 XGE 对调用方完整性的要求

| 调用方式 | 结果 |
|----------|------|
| High 上下文执行 `xgConsole /Rebuild XGETasks.xml`（含 UBT 的全部参数） | 正常产出 `Build ID` 并实际编译 |
| Low 上下文（MSBuild Exec）执行同一命令 | **`Processing is unable to continue due to the Agent Service is not running.`**，退出码 3 |

结论：**IncrediBuild 本身是好的**，是 Low 调用方被拒。

排查过程中逐项验证并排除，记录以备后续参考：

| 假设 | 排除依据 |
|------|----------|

## 5. 修复动作

唯一必要动作：**移除仓库根目录的 `Low` 完整性标签**（继承性标签，清除后自动传播到所有子目录）。

```powershell
# 概念上等价于：把该目录的 SACL（强制完整性标签）清空
# 由于 icacls 没有"删除标签"的口令，实际通过 SetNamedSecurityInfo 完成：
#   SECURITY_INFORMATION = LABEL_SECURITY_INFORMATION (0x10)
#   SACL = NULL  → 移除强制完整性标签
```

同时撤销了排查过程中的临时改动，全部恢复原状：

- `%TEMP%`、`C:\ProgramData\Epic`、`C:\Users`、`C:\ProgramData`、`AppData` 上临时添加的 Low/Medium 标签 → 全部移除
- `Engine\Build\BatchFiles\DotnetDepends.bat` 的临时改动 → `git checkout` 还原（无 diff）
- `%APPDATA%\Unreal Engine\UnrealBuildTool\BuildConfiguration.xml` → 还原为默认空配置（XGE 默认启用）
- 临时目录 `D:\temp`、3.8 GB 测试拷贝 `C:\dotnet_test` → 已删除

## 8. 经验与防范

### 8.1 核心认知

> **"Access is denied" 不一定是权限问题。**
> 当同一台机器上"只有部分程序写不进某些目录"时，优先怀疑**强制完整性级别（Mandatory Integrity Control）**，而不是 DACL。

DACL 决定"谁有什么权限"，完整性标签决定"这个等级的进程能不能往上写"。两者互不替代：DACL 给了 `(F)`，标签仍可能拒绝。

### 8.2 防范清单

1. **不要让带沙盒的 agent 工具在重要仓库上写 ACL**。Codex / 类似工具会为限制写入范围而给工作目录打 `Low` 标签；一旦仓库被标，后续所有从该目录启动的编译工具都会降级。
2. **接手他人机器、复用旧工作区、或"突然不能用"时**，先扫一眼标签：

   ```bat
   icacls "D:\Work\dev_git\UnrealEngine561" | findstr /C:"Mandatory Label"
   ```

   Windows 正常目录通常**没有**标签输出。
3. **构建类工具对完整性敏感**：`dotnet`、`cl.exe`、`MSBuild`、`xgConsole` 在 Low 下会出现各种"权限明明够却写不进"的怪象；IncrediBuild 的 XGE 直接要求 High 调用方。
4. **排查顺序**：先看进程令牌等级 → 再看目录标签 → 再看 DACL → 最后才怀疑软件装坏/版本不匹配。

### 8.3 常用自查命令

```bat
:: 目录是否带完整性标签（有输出就要警惕）
icacls "D:\path\to\repo" | findstr /C:"Mandatory Label"

:: 当前进程的完整性级别
whoami /groups | findstr /C:"S-1-16"
::   S-1-16-12288 = High    S-1-16-8192 = System
::   S-1-16-4096  = Medium  S-1-16-2048 = Low

:: 快速判定"位置是否影响降级"：把同一 exe 拷到 C:\ 下对比运行
```
